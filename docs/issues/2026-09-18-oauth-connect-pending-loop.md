## 증상

OAuth 로그인 자체는 성공하는데, 플러그인 설정 화면이 그 결과를 **받아 반영하지 못하고 대기 상태에 머문다.**

1. Settings → CMDS Achmage → OpenAI Plan → **Connect**
2. **Login to OpenAI** → 브라우저 창 열림 → 로그인 → 프로젝트 선택 → 브라우저에 *"이제 꺼도 됩니다"* 안내가 정상 표시됨
3. 플러그인 설정으로 돌아오면 **"인증을 기다리고 있습니다" 스피너가 계속 회전**
4. 기다려도 `Connected`로 전환되지 않음

즉 **브라우저 쪽 플로우는 완료**되었는데 플러그인 쪽이 완료 신호를 수신·반영하지 못하는 상태다.

## 우회 (현재 사용자 안내 중)

1. 설정 창을 닫고 **Obsidian을 완전히 종료** (창만 닫지 말고 앱 종료)
2. 다시 실행 → Settings → Community Plugins → CMDS Achmage
3. **Connect를 한 번 더 클릭** → 즉시 `Connected` 표시

재시작 후에는 **추가 로그인 없이** 붙는다. 토큰은 이미 저장돼 있고 **UI 상태만 갱신되지 않았다**는 정황이다.

## 추정 원인 (미검증)

- 콜백 수신 후 설정 화면의 상태가 **리렌더되지 않음** — 저장은 됐으나 화면이 pending에 고정
- 또는 콜백 리스너가 설정 탭 생명주기에 묶여 있어, 브라우저를 다녀오는 사이 **리스너가 해제/중복 등록**됨
- 폴링 방식이라면 **완료 조건 판정 또는 타임아웃 처리 누락**

재시작으로 해소된다는 점이 세 가설 모두와 부합하므로, 먼저 **연결 완료 직후 저장된 토큰 유무**를 확인하면 "저장은 됐는데 UI만 못 따라온 것"인지 바로 갈린다.

## 코드 확인 (2026-10-14, `main` `f193dfb` 기준)

**확인된 사실 (소스 열람)**

- 대기 스피너는 `ConnectOpenAIPlanModal.tsx`의 `isWaitingForCallback`이다. `startCodexCallbackServer()` → `exchangeCodexCodeForTokens()` → `applyTokens()`가 모두 끝나야 `finally`에서 꺼진다.
- `startCodexCallbackServer()`(`src/core/llm/codexAuth.ts`)는 `localhost:1455`에 임시 HTTP 서버를 띄우고, 5분 타임아웃(`CALLBACK_TIMEOUT_MS`)을 둔다. 타임아웃이 나면 수동 URL 붙여넣기 안내가 뜨도록 되어 있다.
- 콜백을 받으면 브라우저에 성공 페이지를 **먼저** 보낸 뒤 `finalize()`를 부른다. `finalize()`는 **타임아웃을 먼저 해제**하고, 코드 전달(`resolve`)은 `server.close()`의 완료 콜백 **안에서만** 한다.
- 토큰 교환 `fetch`에는 별도 타임아웃이 없다.

**유력 가설 (추론 — 미재현)**

`server.close()`의 완료 콜백은 열린 연결이 모두 끝나야 호출된다. 브라우저가 성공 페이지를 받은 연결을 keep-alive로 붙잡고 있으면 콜백이 늦어지거나 오지 않을 수 있다. 이때 타임아웃은 이미 해제된 상태라 **스피너가 끝나지 않는다.** 브라우저는 성공 페이지를 보여 주므로 "브라우저는 완료, 플러그인은 대기"라는 현장 증상과 맞는다. 재시작 후 로그인 없이 붙는 것도 OpenAI 브라우저 세션이 남아 있어 인증 화면이 바로 통과되기 때문일 수 있다(토큰이 미리 저장됐다는 근거는 아님).

→ 위 "추정 원인"의 세 번째(타임아웃 처리 누락)에 가장 가깝다. 수정 전 재현으로 확인할 것.

## 확인이 필요한 것

- [ ] Connect 직후 `data.json`에 토큰이 실제로 기록되는가 (기록된다면 순수 UI 문제)
- [ ] 콜백 응답 후 `server.close()` 완료 콜백이 실제로 호출되는가 — 응답에 `Connection: close`를 넣거나 `closeAllConnections()`를 쓰면 해소되는지
- [ ] 콜백 핸들러가 한 번만 등록되는가 — 설정 탭 재진입 시 중복/해제 여부
- [ ] 대기 상태에 **타임아웃과 실패 메시지**가 있는가 — 코드상 5분 타임아웃은 있으나 콜백 수신 시점에 해제되므로 이후 단계는 무한 대기 가능
- [ ] Windows/macOS 차이 여부 — 현장은 Windows 렌탈 PC, 강사는 macOS로 **양쪽 모두 발생**
- [ ] Claude 연결 경로에도 같은 문제가 있는가 (강의에서는 OpenAI만 시연)

## 고칠 때 같이 보면 좋을 것

첫 사용자가 가장 먼저 만나는 화면이라 **실패해도 다음 동작을 알 수 있어야** 한다.

- 대기 상태에 타임아웃(예: 60초)과 함께 *"연결이 확인되지 않으면 Obsidian을 재시작한 뒤 Connect를 다시 눌러주세요"* 안내 노출
- 성공/실패를 모두 명시적으로 표시 (현재는 성공만 표시되고 실패는 무한 스피너)
